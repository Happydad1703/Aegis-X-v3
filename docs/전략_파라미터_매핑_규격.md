# 전략 서술(자연어) ↔ 엔진 파라미터(수치/규칙) 매핑 규격 (Aegis-X v3)

**목적**: “전략 문장”이 **어디에서** 어떤 **입력 dict/조건식**으로 내려가는지 문서로 잠금. Cursor가 API에서 계산하거나, 엔진에서 DB를 읽거나, 스냅샷을 repo 밖에서 쓰는 실수를 막기 위함.

---

## 1. 원칙

- **전략 서술** (예: “120MA 기울기 +, 60MA > 120MA면 유지”) → **엔진 입력/파라미터**로만 변환.
- **조건 평가 위치**: **engines/** (regime_engine, core_engine 등) — 순수 함수(dict in → dict out).
- **데이터 읽기**: 엔진은 DB를 직접 읽지 않음. Worker가 DB에서 읽어 **입력 dict**로 넘김.
- **기록**: 엔진 산출은 **core/snapshot_repo.py** 경유로만 **engine_snapshot**에 기록.
- **UI/API**: engine_snapshot만 조회. 계산·조건 평가 금지.

---

## 2. Core Force 예시 매핑

| 전략 서술 (자연어) | 평가 위치 | 입력(엔진에 넘길 dict) | 산출(스냅샷/키) | 비고 |
|--------------------|-----------|-------------------------|------------------|------|
| “120MA 기울기 +, 60MA > 120MA면 유지” | regime_engine 또는 core_engine | `{ "ma_120_slope": float, "ma_60": float, "ma_120": float, ... }` (Worker가 DB/수집 결과에서 구성) | regime_current 또는 전략 유지 플래그 | SE-39 Regime 수학 명세와 통일 |
| “저회전(거래 억제)” | gates (pre_trade_gate, risk_gate) | ROE·한도 설정; 스냅샷(regime_current, risk_guard) 참조 | Gate 통과/거부, incident_log | 엔진이 아닌 Gate에서 강제 |
| “승격(Swing→Core)” | 엔진에서 후보 산출 | allocation, fleet_budget, 성과 지표 | 스냅샷(승격 후보/플래그) | 실행은 gate/command로 분리 |

---

## 3. 입력 dict 구성 책임

- **Worker**(engine_worker, ingest 연동) 또는 **전용 레이어**가 DB(ext_event_raw, macro_context, engine_snapshot 등)에서 읽어, 엔진이 기대하는 **입력 dict**를 구성.
- 엔진 함수 시그니처 예: `compute_regime(inputs: dict) -> dict`, `compute_core_hold(inputs: dict) -> dict`.
- **엔진 내부**에서 `session`, `text()`, `create_engine`, `requests` 등 사용 금지.

---

## 4. 금지 패턴 (Cursor 실수 방지)

| 금지 | 올바른 위치 |
|------|-------------|
| API에서 120MA/60MA 계산 | engines/ 에서 계산; 결과는 snapshot으로 저장 후 API는 조회만 |
| 엔진에서 DB 세션으로 직접 조회 | Worker가 DB 조회 → dict로 엔진에 전달 |
| engine_snapshot에 엔진/API 다른 경로로 INSERT | 오직 core/snapshot_repo.py 경유만 |
